# 自然接话：设计与取舍

## 要处理的问题

同一句话，在私聊、真实群聊和转发记录里，含义和回应方式可能不同。只靠“少说几句”“像真人”“别用 Markdown”无法解决这种区别，也无法避免连续检讨、重复笑话和丢失原话题。

插件先处理当前交流的对象与目的，再约束表达。用户只是随口分享时，不自动扩成项目方案；用户明确要调研或安装时，照常用工具完成工作。

## 保留什么

查证习惯、工具能力、明确完成状态和可取回文件都应保留。需要改变的是展示信息的时机和比例：闲聊不倾倒内部日志，正式任务不因为追求短答删掉关键依据。

稳定身份与关系由原工作区规则提供；本插件不预装具体人物。核心技能只写跨场景可复用的指导，参考资料按需加载。

## 借鉴与不采用

| 来源方向 | 借鉴 | 不直接移植 |
| --- | --- | --- |
| MaiBot | 根据语境选择表达，允许零选择；区分聊天规划与回复 | 每条消息强制增加多个模型步骤 |
| DSH QQ 项目 | 区分会话、转发、发言对象、记忆来源与修正 | 固定长等待、随机情绪、模拟生活冒充现实 |
| AstrBot 生态 | 场景感知、可核查的记忆证据、受控的接话 | 完整接管现有工具管线、重复注入上下文 |
| SillyTavern / elizaOS | 按用途区分风格，使用对话样例 | 固定台词、堆积长背景 |
| Mem0 / Graphiti / Letta | 来源、时间、修订和变更可追踪 | 在指令插件里重新实现数据库与后台调度 |
| AIRi / Open-LLM-VTuber | 认识到打断和轮次同步对语音体验的重要性 | 宣称本插件能增加全双工语音；强制一两句和每轮追问 |
| Humanizer 系列 | 检查空话、重复、模板表达 | 用禁词表替代语境判断，或删除真实身份说明 |

## 记忆怎么处理

插件使用宿主已有、获授权的记忆机制。写入前区分用户原话、引用、助手推测、计划和模拟内容，保留主体、时间、条件与纠正关系。没有宿主机制时，只使用当前可见上下文，不声称已经持久化。

不建立好感度或情绪计分器，不主动保存整段聊天，不启动自动私信。该插件也不会把一次玩笑固化为用户长期性格。

## 如何评估

格式校验回答“文件能不能被读取”，安装检查回答“宿主有没有发现并启用”，连续对话评估回答“实际回复有没有改善”。三者分开记录。

[review-cases.json](../plugins/natural-dialogue/skills/natural-dialogue/references/review-cases.json) 提供 16 个场景，按行为和结果审阅，不用关键词命中率、固定句数或“AI 检测分数”代替评价。

对有外部动作的案例，应使用隔离环境或模拟输入；评估材料不授权真实发布、读密钥、发消息或新增付费模型调用。
